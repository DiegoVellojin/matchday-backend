## 🔐 0. MÓDULO: AUTENTICACIÓN (`/auth`)
*Gestión de identidad, sesiones seguras y recuperación de acceso.*

### 0.1 Iniciar Sesión con Google
- **Endpoint:** `POST /auth/google`
- **Descripción:** Intercambia un `idToken` de Google por un JWT interno.
- **Payload:** `{ "id_token": "string" }`
- **Response:** `{ "access_token": "JWT", "token_type": "bearer" }`

### 0.2 Registro Local (Email/Password)
- **Endpoint:** `POST /auth/register`
- **Payload:**
  ```json
  {
    "nombre_usuario": "Nombre",
    "email": "user@example.com",
    "password": "password123"
  }
  ```

### 0.3 Iniciar Sesión (Email/Password)
- **Endpoint:** `POST /auth/login`
- **Payload:** `{ "email": "user@example.com", "password": "password123" }`

## 🛡️ 2. MÓDULO: EQUIPOS (`/teams`)
*Gestión de clubes y membresías.*

### 2.1 Crear un Equipo
- **Endpoint:** `POST /teams`
- **Payload:**
  ```json
  {
    "nombre_equipo": "Elite Strikers",
    "fk_id_deporte": 1,
    "url_logo_equipo": "https://...",
    "descripcion_equipo": "Motto del equipo",
    "esta_reclutando": true,
    "max_miembros": 15
  }
  ```

### 2.2 Ver Mis Equipos
- **Endpoint:** `GET /teams/me`
- **Descripción:** Lista los equipos donde el usuario es miembro aceptado.
- **Response:** Lista de equipos con objeto `deporte` anidado.

### 2.3 Generar Link de Invitación
- **Endpoint:** `GET /teams/{id_equipo}/invite-token`
- **Descripción:** Genera un token JWT (expira en 30m) para compartir.
- **Response:** `{ "invite_token": "string", "expires_in": "30 minutes" }`

### 2.4 Unirse vía Token (Entrada Directa)
- **Endpoint:** `POST /teams/join-with-token`
- **Payload:** `{ "token": "string_token" }`
- **Nota:** El usuario entra automáticamente con estatus `aceptado`.

### 2.5 Solicitar Unirse (Manual)
- **Endpoint:** `POST /teams/{id_equipo}/join-request`
- **Descripción:** El usuario solicita entrar. Queda en estatus `pendiente`.

### 2.6 Ver Solicitudes Pendientes (Solo Capitán)
- **Endpoint:** `GET /teams/{id_equipo}/pending-members`
- **Response:** Lista de usuarios esperando aprobación.

### 2.7 Responder a Solicitud (Solo Capitán)
- **Endpoint:** `POST /teams/{id_equipo}/respond-request`
- **Payload:** `{ "user_id": 123, "accept": true }`
- **Nota:** Si `accept` es `false`, la solicitud se elimina de la DB.

## 🛠️ ESTÁNDAR DE RESPUESTAS DE ERROR
Todas las fallas siguen el esquema `{"detail": "mensaje"}`.

| HTTP | Escenario |
| :--- | :--- |
| **400** | Datos inválidos o lógica de negocio fallida (ej: ya eres miembro). |
| **401** | Sesión expirada o token inexistente. |
| **403** | Acción prohibida (ej: no eres el capitán de este equipo). |
| **404** | Recurso no encontrado. |
| **409** | Conflicto (ej: el equipo ya tiene el máximo de miembros). |
